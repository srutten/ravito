# Exploitation et opérations

## Runbook — Plateforme indisponible

1. vérifier le statut ;
2. activer la communication de crise ;
3. identifier application, base ou fournisseur ;
4. passer en lecture seule si possible ;
5. restaurer le service ;
6. vérifier les missions ;
7. documenter l'incident.

## Runbook — Compte coordinateur compromis

1. suspendre le compte ;
2. révoquer les sessions ;
3. vérifier les actions récentes ;
4. suspendre les missions suspectes ;
5. contacter l'organisation ;
6. préserver les preuves ;
7. réinitialiser les accès ;
8. produire un rapport.

## Runbook — Fuite de position

1. masquer toutes les positions précises ;
2. révoquer les URLs ;
3. identifier le périmètre ;
4. suspendre les accès ;
5. conserver les logs ;
6. notifier les responsables ;
7. appliquer la procédure de violation.

## Runbook — File de notifications bloquée

1. inspecter la profondeur ;
2. désactiver les retries agressifs ;
3. identifier le fournisseur ;
4. basculer si prévu ;
5. prioriser les messages critiques ;
6. relancer ;
7. vérifier les doublons.

## Sauvegarde

- fréquence ;
- rétention ;
- chiffrement ;
- séparation des accès ;
- test de restauration ;
- preuve du test.

## Continuité

La plateforme doit avoir une procédure alternative :

- téléphone ;
- SMS ;
- radio institutionnelle ;
- tableur local ;
- fiche imprimable ;
- liste des points de rassemblement.

## Support

Définir :

- horaires ;
- niveau 1 ;
- niveau 2 ;
- sécurité ;
- escalade ;
- contacts ;
- délai de réponse ;
- conservation des tickets.

## Maintenance

- dépendances ;
- certificats ;
- documents expirés ;
- comptes inactifs ;
- sauvegardes ;
- tests de restauration ;
- exercice périodique.
